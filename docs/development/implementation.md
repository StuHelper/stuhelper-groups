# Groups 实施状态

目标群关闭机器人、队列满或操作者撤权时，源群继续投递。警告成功后，派生禁言被拒也会保存警告结果。

申请与实际入群分别推进。已准入的群成员切换口令模式后继续保留准入，群内欢迎和提醒以实际入群为前提。到期踢出失败可在核对时重试。

自动拉黑使用永久期限，禁言单独采用配置秒数。举报处置检查留存、状态和已启用的建议，重复建议只执行一次。

批量预览先校验群管理权限。执行遇到基础设施故障时按原键重试，已成功的目标复用收据。批量键上限为 128。

举报分析向模型只发送举报原因与消息正文。模型输入由服务端显式选择字段。锁粒度、资格事实预取与 AI 锁外调用见并发改进 PR #6。

一次资格变更按本人和学校读取当前事实，在短事务中重验关联群并原子更新成员、inbox 与 outbox。已消费的事件和旧修订直接确认。

提交或重放举报前校验本人在目标群的成员关系。未加入和已退出者收到相同的拒绝结果。

保存配置时校验名片模板。渲染只解析原模板中的字段，字段值按原文插入，并按字符数检查结果上限。

路径、分页和写入文本在进入数据库前校验编码。文本长度按 Unicode 码点计数，配置请求体容量覆盖多字节文本。

同一操作者可在不同群和动作中复用键。收据兼容升级前已完成的请求，同一作用域的不同载荷仍会冲突。

源群管理员可以停用已有订阅。启用时仍检查目标群发送权限，变更与审计在同一事务提交。

已入群的豁免成员可使用娱乐功能，当前黑名单仍生效。自助禁言失败、取消或提前解禁时更新期限，豁免清除旧宽限期，并拒绝矛盾学籍阶段。

链接协议名按大小写无关匹配，一条消息命中多个关键词时只记录一个关键词标签。

分页集合只接受声明的查询参数。契约描述群和学校标识、骰子与黑名单时长限制。投递列表的契约操作名为 listDeliveries，Go 和 TypeScript SDK 兼容原有 listDeliverys 名称。

按首次失败的时间计算人工处理窗口。停机时确认已完成投递，维护事务回滚后返回空游标。

## 当前实现

OpenAPI 0.4.0 使用 /api/v1/groups 前缀，Go/TypeScript 客户端、HTTP Handler、Service 与 PostgreSQL Repository 已建立。群与学校关联、分范围管理、本人申请进度、三项绑定和资格判断、动态口令、宽限期、恢复、延期、豁免与自动移出均由服务端处理。

群名片采用单遍占位符解析，提供无副作用的 card_preview 预览与我的群 missing_card_fields 缺失字段键提示，性别未知使用中性分隔符。动态口令维护单调 password_epoch，已恢复入群成员在口令轮换后保留资格，未入群申请者按最新代数重验。

群管理提供警告、禁言、解禁、踢出、黑名单、关键词、链接、频率、防复读、规则预览、观察名单、举报分析与反馈。AI 建议独立保存，执行只采用已启用的动作和当前授权。

欢迎提示与群规则模板可配置。批量管理先预览，执行逐项返回结果。历史成员通过相同资格规则检查，保留延期和豁免。各订阅接收目标独立执行，不合并成功与失败结果。

娱乐功能提供骰子、自助禁言、冷却和保底，未配置不执行，并在 Result 中返回骰子面数、禁言秒数和保底剩余次数；错误响应通过 Problem 子码、字段名与 Retry-After 区分冷却、容量与配置联动校验原因。自助禁言只作用于发起者，不写违规记录。管理员可解禁，普通用户没有自行解禁能力。

消息留存默认关闭，到期读取被拒绝并可分页删除。撤回事件在有效留存期内保留原发送者、正文与图片附件引用，撤回内容查看不写业务查看审计。机器人消息与成员进退分别按单条消息和单个成员维护修订流。其他机器人动作保存授权后的待执行记录及实际执行结果审计。

业务写入、审计和 outbox 在同一事务，提交后 pg_notify。inbox 拒绝同 ID 内容变化，忽略重复与旧修订。发送器使用部分索引、LISTEN、60 秒补读及退避队列。

群列表返回 GroupSummary，集合各有独立分页类型并直接解码为目标结构体。HTTP 路由、Event 与 UpstreamEvent 支持透传可选 traceparent，串联 outbox、Execute 与 Fanout 链路追踪。

配置采用 expected_revision 比较更新，口令只在请求中接收并保存带盐摘要。命令按 kind 验证必填字段，错误码采用 groups_ 枚举。

outbox 提供带排除主题和 limit 的 PendingOutbox，以及幂等 ConfirmOutbox。GroupsForOwner 提供有界成员反查，Consume 按上游 owner 在同一事务内重算关联群，Sweep 保留为周期性核对与期限处理。

Web 通过 GET /api/v1/groups/me 查询自己的成员和申请记录。本人查询复用 owner 反向索引和资格判定，区分缺失条件、未知事实和依赖失败，不返回管理信息，不触发业务写入。

Consume 接受 qq-binding.owner-bindings.changed.v1，并按提供方实际封套检查 subject、owner、十进制 ID 与 int64 修订的一致性。已有去重和旧修订规则不变，不支持的类型继续返回 ErrInvalid。

## 接入限制

groups 仅依赖自有接口、公开 platform 与公开第三方库。资格、字段许可与机器人身份类型定义在 dependencies.go；verification、profiles 和 qq-binding 的事实读取、DTO 转换及错误映射由 backend 实现。

机器人执行器、身份反向解析、图片媒体代理和实时工作台推送由 backend 与 Koishi 装配。本仓使用模拟机器人验证实际成功、失败和未知结果，不访问真实 QQ。

Repository 拆分无锁只读快照事务 ReadOnly 与按作用域哈希升序加锁的 ScopedTransaction，纯查询接口不加 advisory lock，单群与多群写入按确定顺序细粒度加锁。AI 分析使用独立 5 秒超时并在获取写锁前预取，资格事实也在锁外预取后于写事务内复核状态。

远程仓库为 StuHelper/stuhelper-groups，候选通过 feat/backend-decisions 草稿 PR 验证。现有模块不在本任务写入范围，backend 依赖、工作区锁、管理端和 Koishi 未修改。
